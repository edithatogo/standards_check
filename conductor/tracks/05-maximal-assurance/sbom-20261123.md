# Maintained dependency inventories

The registered `baseline` supply-chain policy requires dependency review and an SBOM.
The [workflow](../../../.github/workflows/sbom.yml) generates nine CycloneDX inventories from
the actual checked-out inputs on every pull request and push to `main`, with manual dispatch
also available. Branch protection must require its `Maintained dependency inventories` job
alongside `assurance`; configured source and local qualification alone do not establish hosted
acceptance.

Python counts include the isolated environment's bootstrap `pip`. Each environment passes
`pip check`; its full `pip inspect` identity set must equal the Syft inventory. Closed profiles
must additionally contain exactly their declared pins plus `pip`. The test profile's transitive
versions are an observed resolution, not a reproducible source lock. Installation reports retain
the actual selected distributions and download hashes. Syft captures dependency relationships
available in installed metadata; these reports do not establish runtime reachability.
Python inventories describe the selected interpreters on Linux amd64; they do not cover other
platform-marker branches. The two kernel pins come from the existing qualification workflow's
literal two-version loop. Both requirements files and that workflow are hashed as source inputs;
unexpected loop changes fail before installation. These optional qualification profiles remain
separate from the ordinary legacy host runtime.

The native npm inventories must contain every locked name/version identity, including dependencies
absent from the host's installed tree. The API report includes `express-rate-limit@8.7.5` and
`ip-address@10.7.6`. Repeated lock locations may share one CycloneDX component identity.

## Evidence and failure semantics

Each profile writes `bom.cdx.json`, `receipt.json` and `SHA256SUMS`; Python profiles also retain
installation, consistency and environment reports. Receipts contain the actual checkout commit,
input and generator hashes, tool versions, scope, package counts and final outcome. By default,
input bytes must match that commit, and no input may change during generation. A failed command,
missing identity, unexpected identity or ecosystem, source drift or stale output directory fails
the command. Python requirement pins are validated before environment creation or installation.
Failed receipts are uploaded for diagnosis and are never promoted to successful inventories.

The CLI's `--allow-dirty-inputs` is for local qualification only and names every modified input.
The workflow never uses it. PR runs inventory GitHub's checked-out merge commit, whose identity is
retained in the receipt. A default-branch dependency-graph export is not used as a PR inventory.

This is a dependency inventory, not release provenance or a binary/container SBOM. It excludes OS
packages, interpreter and compiler binaries, bundled native libraries inside wheels, build-script
downloads, separately selected deployment environments and historical requirements preserved
inside the imported source snapshot. The maintained `requirements/legacy-standardflow.txt`
profile is covered; historical `legacy/standardflow/requirements.txt`, `scripts/requirements.txt`
and `scripts/petri_net_generation/requirements.txt` are not promoted to current authorities.
Vulnerability scanning, licence approval and reproducible release qualification remain distinct.
